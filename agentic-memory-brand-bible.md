## 0. Brand Name & Rationale

### Recommended Name: **Lumen**

**Etymology:**
- Latin *lūmen* = "light, source of light, day, clarity, distinction"
- Root of *illuminate*, *luminous*, *luminary*
- In biology: the inner space of a tube or cavity — the *lumen* of a blood vessel is where flow happens. The *lumen* of the endoplasmic reticulum is where memory (protein synthesis) is stored and retrieved.

**Why Lumen:**

| Criterion | Score | Rationale |
|---|---|---|
| Memorability | 5/5 | Two syllables, familiar root, exists in English, easy to spell |
| Meaning-fit | 5/5 | Light = the shared medium in which memory (past light) and context (present light) exist. A lumen is both a **cavity** (the palace rooms) and a **flow channel** (the context window) |
| Visual identity | 5/5 | Endless logo possibilities: lightbulb, torch, eye, aperture, glowing orb, concentric rings |
| Technical identity | 4/5 | `lumen`, `lumenctl`, `liblumen`, `lumen-core` — all natural. Python package: `lumen`. |
| Ownability | 4/5 | "Lumen" is used in some product names (Lumen database, Lumen appliance) but none in agentic AI memory. Risk is moderate — defensible with trademark on AI agent use class. |
| International | 5/5 | Same spelling/root in French, Spanish, Italian, Romanian. No negative connotations across major languages. |
| Extension | 5/5 | Ecosystem names: Luminary (contributor), Illuminate (onboarding), Glow (status indicator), Prism (analytics), Beam (sync/shard), Lens (query tool) |

**Tagline candidates:**
- *Lumen: Where memory meets context*
- *Lumen: Light across time*
- *Lumen: Illuminate your agent*
- *Lumen: Twin forces, unified mind*
- *Lumen: The palace in light*

## 2. Visual Identity

### 2.1 Logo Concepts

#### Concept A: **The Vesica** (Recommended)

Two overlapping circles of equal radius, offset so each centre lies on the other's circumference. The intersection forms the *vesica piscis* — the most ancient symbol of unity between two forces.

```
        ┌───┐
     ┌──┤   ├──┐
     │  │ ✦ │  │     ← the eye/light at the intersection
     └──┤   ├──┘
        └───┘
    Memory  Context
    (cold)  (warm)
```

**Meaning:**
- Left circle = Memory (Mnemonic Force) — deeper, cooler blue/purple
- Right circle = Context (Contextual Force) — warmer, active amber
- Intersection = Lumen — the light at the union, the agent's cognition
- The eye is also an aperture — light entering (context being assembled from memory)
- Three elements (two circles, one lens) mirror the three-tier memory hierarchy (event → preference → profile)

**Variants:**
- Full colour: two-toned circles with luminous intersection
- Monochrome: single linework with negative-space eye
- Simplified: "lumen" wordmark with the vesica as the dot over the 'u'

#### Concept B: **The Torch**

A stylised torch where:
- Base = stacked blocks (rooms of the palace) — geometric, stable
- Flame = flowing upward (context window, attention, light) — organic, dynamic
- The flame and base share a continuous line — twin forces

**Meaning:** Memory as fuel, context as flame, cognition as light. Strong sovereign AI metaphor (carries its own light, needs no external fire).

**Risk:** Generic — torches are overused in tech branding.

#### Concept C: **The Aperture**

A camera-style iris aperture:
- Closed aperture (narrow focus) = precise retrieval, low attentional temperature
- Open aperture (wide) = broad exploration, high attentional temperature
- The TFC's attentional temperature `a` literally controls aperture width

**Meaning:** Context is what the aperture lets through. Memory is everything behind it.

**Risk:** Requires explanation. Weak standalone.

#### Concept D: **The Ampersand**

The `&` symbol as the core mark — union of memory & context, palace & window, force A & force B.

**Meaning:** Simple, elegant, the oldest typographic symbol for unity. Nearly 2000 years old (ligature of Latin *et* — "and").

**Risk:** Hard to trademark an existing character. Could work as a secondary mark (the "Lumen &").

### 2.2 Recommended Primary Mark: Vesica Lumen

**Rationale over alternatives:**
- The vesica piscis has 4000+ years of symbolic weight (sacred geometry, mathematics, optics) — *it has never been used in AI branding*
- Mathematically pure: two equal circles, the intersection creates √3 proportions — mirrors the precision of the engineering
- The "eye of light" at centre ties to the name
- Scalable from favicon to billboard
- Works in single colour

### 2.4 Typography

| Use | Font | Fallback | Rationale |
|---|---|---|---|
| Headings (display) | **EB Garamond** | Georgia, serif | 400 years of history; luminous, architectural, timeless. The serif evokes the palace — carved, permanent |
| Headings (UI) | **Inter** | system sans-serif | Clean, highly legible at small sizes, excellent spacing for technical content |
| Body text | **Inter** | system sans-serif | Works across documentation, UI, marketing |
| Code / technical | **JetBrains Mono** | monospace | Ligatures for `->`, `=>`, `!=` — developer-friendly. Distinctive but not distracting |
| Brand wordmark | **EB Garamond** italic | Georgia italic | The "lumen" wordmark in Garamond italic has classical weight |

### 2.5 Visual Design Principles

1. **Light as medium**: Backgrounds should feel like lit paper, not dark glass. Lumen White (#F5F0E8) as default bg, not pure white.
2. **Duality as order**: Every UI should acknowledge the twin-force — two columns, paired cards, split timelines. Not decorative, structural.
3. **Depth through shadow**: Shallow shadows (palace rooms receding), never flat design's uniform lightness. Memory is layered.
4. **Motion as retrieval**: Loading states should animate outward (retrieving from depth), not spin or pulse. Light expanding from a point.
5. **Typography hierarchy**: Headings in Garamond (timeless memory), body in Inter (functional context). The twin forces in type.

### 2.6 Iconography

System icons should follow a consistent style:
- **Stroke-based** (not filled) — outline = context (ephemeral), fill = memory (durable)
- **2px stroke** — clean, modern
- **Rounded square base** for memory icons (rooms, loci, palace)
- **Circular base** for context icons (window, attention, query)
- The combination creates a distinctive visual language

Icons needed:
- Memory: palace, room, locus, chunk, fact, consolidation, forgetting
- Context: window, attention, query, assembly, goal, theory-of-mind
- Twin-force: the vesica, the controller, balance, flux

## 3. Technical Identity

### 3.1 Architecture Naming

The twin-force concept is encoded *in the architecture itself*, not just the marketing.

```
Lumen Core Architecture:

  lumen-core/                    # The twin-force controller
    ├── force/                     # The two forces as first-class modules
    │   ├── mnemonic.rs            # Force A: Memory Palace
    │   │   ├── palace/            #   Topology (rooms, loci, corridors)
    │   │   ├── consolidation/     #   Write path + scheduling
    │   │   └── forgetting/        #   L1-L4 forgetting stack
    │   └── contextual.rs          # Force B: Context Engine
    │       ├── assembly/          #   Context window builder
    │       ├── retrieval/         #   Search algorithms (9.x taxonomy)
    │       └── attention/         #   Budget allocation, intent routing
    ├── lumen.rs                   # The unification — the light at the intersection
    │   ├── controller/            #   TFC: e, a, τ, r state machine
    │   ├── lifecycle/            #   6-operation lifecycle (MARS-inspired)
    │   └── user/                 #   Per-user weights, 7-factor V(m)
    └── sovereign/                 # Edge-specific optimisations
        ├── frqad.rs               # Fisher-Rao distance (SIMD NEON)
        ├── optical.rs             # Progressive quantisation schedule
        └── wear.rs                # Flash-aware write batching
```

**Naming conventions:**
- Memory is *substantive, concrete* (room, locus, chunk, fact, palace)
- Context is *active, verbal* (assembly, attention, retrieval, intent, query)
- The union is *light* (lumen, illumination, beam, prism)
- Forgetting is *natural* (decay, fade, dim, release, not "delete" or "remove")
- Never use "delete" in user-facing APIs — use `forget`, `release`, `dim`

### 3.2 API Design Principles

```python
# GOOD — twin-force visible in the API shape
import lumen

# Force A: Memory operations are nouns (places in a palace)
lumen.memory.store(fact="user prefers dark mode", room="preferences")
lumen.memory.locus("preferences.dark_mode")  # navigate to a locus
lumen.memory.consolidate()  # sleep-phase consolidation
lumen.memory.forget("preferences.dark_mode")  # graceful forgetting

# Force B: Context operations are verbs (actions in the window)
lumen.context.assemble(query="what theme does the user want?")
lumen.context.budget()  # current context window budget
lumen.context.retrieve(similar_to=..., n=5)

# Unification: Lumen operations (the light)
lumen.status()  # TFC state: e, a, τ, r
lumen.controller.adjust(e=0.7, a=0.3)  # manual TFC override

# BAD — flat, no duality
lumen.store(...)  # store what? in what?
lumen.get(...)  # get from where?
lumen.delete(...)  # too aggressive
lumen.search(...)  # search how? with what intent?
```

## 6. Critique & Risk Analysis

### 6.1 Brand Name Risks

| Risk | Mitigation |
|---|---|
| "Lumen" is used by a telecom (Lumen Technologies) | They operate in networking, not AI agent memory. Risk of confusion is low. Legal clearance needed. |
| "Lumen" is a database (Lumen DB — research project) | Research project, not commercial. Name is not trademarked in AI class. |
| Name is too abstract | Counter: the video-game-like concreteness of "Palace", "Room", "Locus" grounds the abstraction at product experience level. |
| "Lumen" has religious connotations (lumen = light in liturgy) | Double-edged: depth for some, exclusionary for others. Brand tone must stay secular-technical. |

### 6.2 Brand Rejection Criteria

We considered and rejected:

| Name | Reason |
|---|---|
| Dyad | Too short, hard to trademark, no visual hook |
| Mneme | Unfamiliar — "nee-mee" is confusing to spell/pronounce |
| Palace | Generic, descriptive, unprotectable |
| Cortex | Overused in AI/neuro tech (Neo Cortex, etc.) |
| Engram | Existing paper, existing product (Engram memory) |
| Echo | Amazon Echo — legal minefield |
| Talus | Medical term (ankle bone) — domain confusion |
| Ampersand | Great visual, impossible to use as a verb/product in speech |

### 6.3 Visual Identity Risks

| Risk | Mitigation |
|---|---|
| Vesica is similar to some med/wellness logos | Differentiate through colour palette (deep navy+amber — not pastels/wellness) and AI-context application |
| Dual-circle logos are common (Pepsi, Mastercard) | The vesica is distinct from adjacent/overlapping circles. The intersection eye sets it apart. |
| EB Garamond heading may feel "too classic" for developer audience | Pair with Inter (modern sans) for UI. Garamond in headlines only. Offer "technical mode" with Inter everywhere. |

### 6.4 Technical Identity Risks

| Risk | Mitigation |
|---|---|
| "Forgetting" language may concern enterprise compliance teams | Pair with "Compliance" module naming, audit logs, GDPR-ready vocabulary. Frame forgetting as *intentional knowledge governance*, not data loss. |
| Twin-force abstraction may seem like unnecessary complexity | The abstraction maps 1:1 to the actual architecture. It's not a marketing overlay — it *is* the architecture. Technical docs demonstrate the concrete benefits in retrieval latency, budget, and per-user personalisation. |
| Sovereign-first positioning limits TAM | Intentional. Sovereign AI is a growing wedge, not a niche. Enterprise and cloud customers can self-host. The constraint differentiates. |
